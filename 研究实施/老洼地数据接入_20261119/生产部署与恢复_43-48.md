# 老洼地生产部署与恢复

## 发布归档

生产模式使用同一个 PostgreSQL 保存日报、回放及运行状态。七份日报、两张监控截图和页尾单元格仍按原件哈希追溯。准备只读挂载目录时，从本项目目录执行以下命令，输出目录应为空。

```sh
PYTHONPATH=. python -B scripts/stage_archive.py "$LAOWADI_ARCHIVE_DIR"
```

`seed/` 保存两份离线导入库，`sources/<SHA-256>/` 保存原件，`standards/` 保存当前规程核验材料。在把新版本挂载给读者之前，保留已发布版本使用的哈希目录。迟到的日报纳入全量种子及完整历史回放后重新发布。发生订正时，先取得批准并核对日报、回放和原件的哈希，再用 `db migrate-archive --allow-corrections` 发布。缺少既有日期、回放与日报哈希不匹配或原件校验失败时拒绝提交。单个读请求持有一致数据库快照，已开始的请求可继续读取此前发布版本。

## 启动工作台

Compose 从部署环境取 `LAOWADI_ARCHIVE_DIR`、`LAOWADI_PG_PASSWORD`、`LAOWADI_AUTH_SECRET`。DSN 中若有特殊字符，直接使用经过 URL 编码的 `LAOWADI_DATABASE_URL`。可继续从本地已有 DeepSeek 配置安全注入 `COAL_API_KEY`、`COAL_API_BASE_URL` 和 `COAL_API_MODEL`。当前使用 `deepseek-v4-pro`。源码、镜像和备份中均无需放置模型密钥。

```sh
docker compose up -d --build
curl --fail http://127.0.0.1:8765/readyz
```

Kubernetes 先创建 `laowadi-power` 命名空间。用 `k8s/secret.example.yaml` 确认键名，由部署环境安全注入 `laowadi-secrets`。通过目标环境的 StorageClass 或预绑定卷满足两个 RWX PVC 和 PostgreSQL 的 RWO PVC。把已暂存的原件及种子填入档案卷，并为备份卷配置应用 UID/GID 10001 写权限。生产镜像及 TimescaleDB 镜像使用可供该环境拉取的版本。应用 `kubectl apply -k k8s` 后，依次观察迁移 Job、API/Worker Deployment 和 Service endpoints。

外部入口域名通过 `LAOWADI_ALLOWED_HOSTS` 配置。K8s 探针使用 `Host: localhost:8765`。历史回放环境用 `LAOWADI_MAX_DATA_AGE_HOURS=0`，且就绪结果显示 `historical_archive`。连续监测环境应按已核定的数据到达周期设置正值，并复验过期告警、就绪摘流与补传后的恢复。库与回放校验、原件、运行态表、Worker 心跳及资料时效可分别从 `/readyz` 的字段定位。进程存活通过 `/healthz` 检查。

## 一致备份与独立恢复

生产备份使用同一 PostgreSQL 快照导出数据和对账计数，同时打包该版本使用的九份已验哈希原件。操作系统、镜像、部署清单、数据库访问凭据和恢复所需角色由目标环境另行交付。请将压缩包与同名 SHA-256 文件一并复制到与源卷分离的受控存储。K8s CronJob 在北京时间每日 02:00 生成恢复点。

```sh
python -B -m laowadi ops backup --output-dir /backups
python -B -m laowadi ops verify-backup --bundle "$BUNDLE"
python -B -m laowadi ops restore --bundle "$BUNDLE" \
  --target-dir "$EMPTY_RESTORE_DIR" --target-pg-url "$TARGET_PG_URL"
```

目标为独立空库，并准备与源兼容的 PostgreSQL 主版本及同版本的 TimescaleDB 和 pgvector 扩展。使用 PG 客户端工具目录 `LAOWADI_PG_TOOL_DIR`，应用镜像内为 PostgreSQL 16。恢复完成后将目标 API 和 Worker 指向新 DSN，从恢复目录挂载 `sources/` 与 `standards/`。已有恢复点由目标数据库直接提供，干净集群的首次归档导入 Job 应跳过。确认源端已停止写入，再切换入口。校验工作台可读、工单与 Outbox 对得上、两套 DAG 检查点可读、Worker 已重新登记、任务事件可续接。历史 SQLite 运行状态继续随离线库保留，新的 PostgreSQL 部署从空运行态开始。

值班实测 RTO 从故障发生计到目标工作台可查。RPO 从故障时刻回溯到最新可恢复快照，应另行验证备份外送完成时间和离线副本可用性。当前每日一次备份在每次均成功且及时外送时，计划窗口约为 24 小时。需要更短 RPO 时应另行部署并验收 PostgreSQL WAL 归档或同步恢复方案。矿方目标环境的存储、网络切换、RTO/RPO 承诺与实际值班签收仍待现场验收。
