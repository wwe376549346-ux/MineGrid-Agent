# 老洼地煤矿配电网健康监测与智能体升级路线

记录日期：2026-11-19  
项目定位：面向煤矿配电网的**电力数据质量检测 → 运行健康评估 → 异常发现与诊断智能体**。  
数据口径：继续以老洼地 35 kV 变电所已归档的 7 份运行日报（2026-11-10 至 2026-11-16）及 2 张监控截图为当前开发与验收依据；所有设备参数、运行日志、保护定值或开关状态缺失之处均显式按“证据不足 / 待矿方核对”登记。

---

## 一、对现有原型的阶段性复盘（4 个主要偏移）

1. **监测维度过窄**：虽然日报库已入库 25 个地面柜 × 4 个电气量（`Uab`、`Ia`、`P`、`cos`），但现有 `monitor.py` 仅监控 4 个柜的有功 `P` 相邻整点变化 ≥ 1,000 kW 及缺测，导致 7 天产生 106 条碎提示（易告警疲劳），却未检测电压偏差、功率因数异常、量测物理一致性、运行方式切换和功率平衡。
2. **智能体职责倒置**：当前 `questions.py` + `agent.py` 用手写正则路由，并预先构造好固定候选列表，大模型仅负责给候选项排序，最终回复也由模板拼接。这使强推理模型花在“低价值排序”上，未承担跨柜关联分析、根因假设生成和规程比对等真正核心任务。
3. **缺证处理过于保守**：只停留在“缺证、待核对日志”，尚未在严守证据边界的前提下，给出“基于现有电气特征的候选诊断假设排序 + 现场排查先后步骤”。
4. **LLM 调用链路与工具维护成本偏高**：`model.py` 采用非流式 + 思考模式 + `max_tokens=512` + 串行单点查询，12 题对照中 5 题因超时或解析失败提前停止；同时多个平行实验目录与手写解析器增加了维护负担。

---

## 二、升级后的目标架构：「双轨制」健康监测与诊断智能体

### 1. Fast Path（确定性电力健康检测与事件聚合引擎 · 无 LLM、毫秒级）
面向全站 25 柜 × 4 指标建立四维健康检测：
- **量测与物理自洽健康**：整点齐全度、零值/冻结值、三相功率一致性比例 $k = P / (\sqrt{3}\cdot U_{ab}\cdot I_a\cdot \cos\varphi)$、持续负功率/异常功率因数及备用柜悬浮电压检测。
- **电能质量健康**：按 GB/T 12325 核查 10 kV 电压偏差（±7%，9.30–10.70 kV）与 35 kV 电压水平，自动聚类 10 kV I/II 段母线电压差；核查带载回路功率因数（`<0.90` / `<0.80` / `<0`）与无功补偿柜状态。
- **拓扑、运行方式与功率平衡健康**：识别单进线带双主变（35 kV 母联运行）、主变/进线全链反向有功（倒送电），并计算 35 kV 侧与主变高低压侧功率平衡，自动区分**SCADA 整点轮询时间偏移（Polling Skew）**与稳态不平衡。
- **分时段动态基线与站级事件聚合**：按 00:00–23:00 建立避峰填谷生产节律基线，将多柜联动聚合成站级事件，区分“常规避峰复产波动”与“反常运行变化”。

### 2. Slow Path（假设驱动诊断 Agent · 按需触发）
- **复合只读诊断工具**：由原子单点工具升级为全站窗口快照、功率平衡核验、分时段基线对照、以及对接已归档国标/规程（`煤矿安全规程_2025_部令17号`、`GB/T 50417-2017`）的条款检索工具。
- **快慢模型分离 + 流式并行调用**：用标准 `openai` SDK（流式 + 重试 + Parallel Tool Calling）替代手写 `urllib`；意图解析与工具选择采用低延迟非思考模式（目标 <5s），复杂根因综合研判单次调用强推理模型（`deepseek-v4-pro`）。
- **三段式证据诊断单 + 程序级护栏**：输出严格分为 ① 已证实的电气事实（附原表单元格，程序强校验防幻觉）→ ② 候选诊断假设及支持/反驳证据 → ③ 缺证项与现场排查 SOP。

### 3. 务实工具选型（一人主做精简栈）
- **模型调用与编排**：官方 `openai` SDK + `Pydantic` / 轻量 `LangGraph`（仅在需要人工补证断点续跑时启用状态图检查点）。
- **数据处理**：标准 Excel 解析库（`xlrd`/`openpyxl`/`calamine`）+ `SQLite` / `DuckDB`（支撑后续分钟/秒级连续时序）。
- **规程与资料检索**：优先用 `SQLite FTS5` / BM25 + 结构化条款元数据索引已有国标与规程，待矿方图纸与定值单规模扩大后再接 `Docling` + 混合检索。
- **工具协议与评测**：工具稳定后用 `FastMCP` 封装统一只读接口；评测先用 JSONL Trace + `pytest` 黄金题库，论文或规模对照阶段按需挂本地 `Langfuse`。
