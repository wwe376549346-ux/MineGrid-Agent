# 老洼地煤矿 · 小时级接入与本地问答

将地面 35 kV 运行日报的整点读数和页尾统计分开入库，并把两张监控截图中柜号及经标注的站间进线对应写入台账。现场资料适用于小时级历史分析和图示关系查询。后续实时接入需要连续现场数据接口或更高频历史记录。

PostgreSQL、Compose、Kubernetes 和备份恢复的入口见[生产部署与恢复](生产部署与恢复_43-48.md)。

## 运行环境与版本说明（v2.2.0）

- **离线最小 CLI 模式（`import / ask / replay / monitor`）**：支持 Python 3.11+ 标准库直接运行，不依赖第三方包。
- **完整企业级工作台与求解模式（`workbench / api / powerflow / storage / dag`）**：需要 Python 3.11+（本项目验收环境为 `../.venv-power`，Python 3.12）并按 [`pyproject.toml`](pyproject.toml) 安装 FastAPI、Uvicorn、Pydantic v2、pandapower、SQLAlchemy 2.0、Alembic 与 psycopg。
- 导入从指定文件夹读取原始 `.xls` 和两张截图，默认写入 `local/laowadi.sqlite3`。对已导入且文件哈希相同的日期再次运行，已有记录只读取不重复插入；遇到同日报日期的文件版本冲突会拒绝整批提交。

```sh
python3 -B -m laowadi import --source "$HOME/Desktop/老洼地煤矿"
python3 -B -m laowadi ask '11 月 16 日一回进线的整点最大有功功率是多少？'
python3 -B -m laowadi ask '中央变电所一回进线由地面哪个柜供电？'
python3 -B -m laowadi replay --date 2026-11-16
python3 -B verify_local.py --source "$HOME/Desktop/老洼地煤矿"
```

直接运行 `python3 -B -m laowadi ask` 可连续提问，例如先问整点最大值，再问「日报页尾的最大值呢？」。未限定口径的当日统计同时列出页尾值和整点计算值。页尾值按原表照录，现有资料对页尾采用的采样频度和极值发生时刻无说明。整点统计的时刻和样本数来自实际整点记录。`--json` 输出工具名、参数、结果状态和证据，`--db` 可指向其他本地 SQLite 文件。回放每行输出一个历史整点，携带原始文件名、表名、行号、列号和哈希。

## 小时级监测回放

监测范围为 303、306、1009、1010 四个柜。程序在历史整点到达后主动输出提示，并在 `local/laowadi_events.sqlite3` 记录触发时刻、规则和源数据。事件入库与回放进度一并提交，相同资料、门槛和模拟参数再跑时复用原运行编号，可查询已归档事件。

两条规则分别处理有功变化和缺测。默认待复核门槛为相邻两个有效整点的有功变化绝对值 ≥ 1,000 kW，这一门槛用于回放筛查。有功读数为空时标记数值缺失。相邻收到的帧相隔超过一小时时，以下一个收到的帧触发整点缺测提示。统计变化只在相邻有效整点间计算，原始正负方向和两个单元格都保留。

```sh
python3 -B -m laowadi monitor
python3 -B -m laowadi ask '11月10日12点303柜为什么提示变化？'
python3 -B -m laowadi monitor --simulate-missing '2026-11-10 10:00:00'
python3 -B verify_monitor.py
```

可指定 `--date` 跑单日、`--threshold-kw` 配置演示门槛、`--seconds-per-hour` 规定回放速度。`--json` 以逐行 JSON 输出提示和完成摘要。`--events-db` 可给回放和问答指定同一个新的事件库文件，便于完整重演。问答默认查询最近建立的原始历史回放。如需查模拟事件，可直接使用事件编号，或用 `ask --run <回放编号>` 限定模拟回放。完成摘要包含回放编号。

原始整周回放验收为 168 帧、106 条待复核有功变化、0 个整点缺测。模拟回放略过 11 月 10 日 10:00，系统在收到 11:00 帧时检出这一处缺测。303 柜当日 11:00 至 12:00 有功从 1,071.84 kW 变为 4,479.96 kW。事件记录变化 +3,408.12 kW 及 `1110.xls` 的 `D15`、`D16`。历史问答仍依据整点或日报页尾各自的统计口径。

## 只读 Agent Loop

用事件编号或「柜号 + 日期 + 触发整点」定位事件，再对照另一柜在同一对整点的有功读数。可在另一个分句中指定一个柜号及供电方向。连续问答中，先查事件，再问「306 柜同期有功呢？」可以沿用上一次查到的事件。单项查数、事件和拓扑查询沿用原工具的直接调用。

```sh
python3 -B -m laowadi ask 'LW-000010，306柜同期有功也变化了吗？再查1009柜下游。'
python3 -B -m laowadi ask --json '11月10日12点303柜提示变化，比较306柜同期有功。是不是跳闸导致的？'
python3 -B -m laowadi ask --max-tool-calls 2 'LW-000010，比较306柜同期有功。'
python3 -B verify_agent.py
```

例中的编号来自现有整周档案。另建事件库后可用日期、整点和柜号查询该库中的编号。303 柜有功在 11:00 至 12:00 增加 3,408.12 kW，306 柜减少 204.41 kW。`1110.xls` 中的 `D15`、`D16` 与 `H15`、`H16` 分别记录两柜前后读数。1009 柜的图示下游是中央变电所 1101 柜。

每轮最多执行四次只读查询。程序从事件证据取得完整时刻，再校验对照读数的时刻与日报版本。时段错位会提示澄清，缺少读数、日志或达到预算时会列出已确认的证据和待查项。现场原因需要对应时段的运行日志、开关变位记录或保护动作记录。`--json` 中的 `steps` 包含实际调用参数和证据，`comparisons` 给出已核验的有功变化，`stop_reason` 和 `pending` 记录停止原因及待查项。日报库和事件库均以只读方式打开。

默认由本地规则选择下一步。可用 `ask --agent-model` 启用兼容 Chat Completions 函数调用的模型端点，通过 `COAL_API_BASE_URL` 和 `COAL_API_MODEL` 配置。远程端点使用 HTTPS 和 `COAL_API_KEY`。可选项为 `COAL_API_THINKING`、`COAL_API_TIMEOUT_SECONDS` 和 `COAL_API_MAX_OUTPUT_TOKENS`。模型收到问题、候选调用及已执行查询的参数。原始资料、实际读数、文件哈希和工具结果留在本地。程序只接受一个获准的候选调用，重复或越界请求会停止，最终答复依据实际工具结果生成。

## 深度诊断的撰写与核验

二号主变反向有功查证先核对 306、312、1006 三柜同一整点的有功。三柜同负时，DeepSeek 每轮根据前一轮回执提交一个假设及其只读查询参数。本地模式按已登记的检验顺序查证。程序核对档案并作出限于当前证据的判定。1027 有功与 A 相电流均为零时，证伪范围限于该柜的归档采样点。缺少同期遥信和采样时标时，母联环流以及极性或轮询偏移均待补证。查询预算用尽时，记录哪些检验尚未执行。

工作台选用 DeepSeek 后提交深度诊断问题，也可用 `laowadi diagnose --model-config`。模型按本轮只读回执撰写现象、多种候选原因、交叉检验、规程适用条件和补证建议。每句带原表坐标、工具结果编号或规程编号。正文中的量值使用本地绑定的证据。若模型提出跨整点差值，程序按原表复算方向、数值和单位。

本地证据检查通过后，应用向配置的模型发起独立语义复核请求，用该句及其引用检查对象错归、无支持的归因和规程适用性。数值、坐标或语义核验失败时，应用把断言编号和理由退回模型。预算用尽或语义复核不可用时，工作台给出核验未通过的状态，候选正文不发布。通过的推演及引用见 `report.diagnostic_claims`，核验计数和反思轮次见 `verification`、`claim_audit_runs` 和 `reflections_triggered`。

## 调压与无功补偿会诊

在「研究工具 → 多智体与治理」选择「11-13 14:00 · 1010 补偿与 II 段过压」。API 为 `POST /api/multi-agent/consult`，同一流程也可从统一 DAG 挂起和恢复。`inter_agent_messages` 保留发送方、接收方、回复关系及结构化载荷，`reactive_arbitration` 保留候选、各稳态筛查结果和待补证项。

量测角色将同一整点的原表读数交给物理角色。问题没有指定整点时，在请求日期范围内优先选取同期高压、低功率因数且模型边界齐全的断面，再按功率因数从低到高、电压从高到低、时间从早到晚选一个整点。物理角色计算基线与单投电容，规程角色依据电压、负载率、无功方向和功率因数约束请求复算。仲裁复核仅调压，以及先调压后补偿的中间稳态与终态。项目用 9.30–10.70 kV 和馈线首端 cos ≥ 0.90 作筛查。地面母线同时对比原始模拟电压和量测加仿真变化量，井下末端使用模拟电压。

11 月 13 日 14:00 的日报记录 1010 柜 cos 0.62 和 1006 柜 10.83 kV（`1113.xls` 的 `BM18`、`Z18`）。同一模型下，单投使送电母线由 10.8322 升至 10.8481 kV。仅调压将母线降至 10.5698 kV，馈线首端 cos 仍约 0.6484。联合候选的母线、末端及馈线首端 cos 分别为 10.5853 kV、10.5797 kV 和 0.9518。档位和容量来自单一断面的等值模型搜索，现场铭牌、档位、开关状态、轻重载及投切过程待核。

## 主动巡检与工单验收

## 可调用的只读工具

| 工具 | 必填参数 | 可选参数与返回 |
|---|---|---|
| `get_hourly_reading` | `station`、`cabinet`、`metric` | `at` 或 `day`。返回指定整点或资料内最后整点及源单元格。 |
| `get_daily_statistic` | `station`、`cabinet`、`metric`、`day`、`statistic` | `basis` 可选 `hourly`、`footer` 或 `both`，默认为 `both`。两种值各自返回源单元格和适用的证据范围。 |
| `get_supply_link` | `station`、`cabinet` | `direction` 可选 `upstream` 或 `downstream`。按两张截图的线路标注返回已整理的直接连接及来源时间。 |
| `get_monitor_event` | 可传 `event_id` 直接定位 | 也可按 `cabinet`、`day`、`at`、`event_type` 或 `run_id` 查询最新匹配事件。返回事件的原始或模拟标识和证据。 |

测量参数可选 `Uab`、`Ia`、`P`、`cos`，统计参数可选 `max`、`min`、`avg`。日报时间使用原始本地钟表标签。缺测、空值及页尾短横线均单独保留。原日报中的正负号保留，符号含义等待设备点表确认。截图线标和台账仅表示该图记载的连接。

```sh
python3 -B -m laowadi tool get_daily_statistic --args '{"station":"S35","cabinet":"303","metric":"P","day":"2026-11-16","statistic":"max","basis":"hourly"}'
```

源 `.xls` 读取器适配该批 xlsLib 导出模板。导入提供源值和坐标溯源，返回整点重算结果时以实际可用整点为分母。设备名称来自已核对的截图并作简写。
