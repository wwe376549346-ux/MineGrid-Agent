# 老洼地煤矿配电网项目 · 企业级投产差距评估

2026 年 11 月 20 日。评估对象是老洼地小时级接入、筛查、主动反馈和值班问答这条实际交付链，同时抽查 Astryx 工作台、模型、交流潮流与部署治理。证据来自当前工作区。文中的“待举证”表示未在本次查阅的交付资料中找到相关记录，矿方或其他系统可能另有安排。

**交付判断。** 现有版本可用于历史日报查证、复盘和专业人员监督下的离线评审。共享值班、持续告警、故障识别、工程结论和生产运维均有未过的验收项。错证通过、漏通知、复核串日三项已能在本机稳定复现，修复都可以立即开始，无须再等一天现场数据。现场效果则需要后续同矿数据和独立复核。

**已能依赖的部分。** 九份原件的 SHA-256 与台账逐份一致。重导同一批资料可去重，同日版本冲突会回滚。七天共有 168 个整点、25 柜、16,800 条整点读数、2,100 条页尾统计，两张图登记 40 个柜、两条站间连接。四柜重新回放得到 106 条有功变化提示。原件可回查到单元格，整点计算和页尾原值分开保存。这些能力值得作为后续验收的基线。[导入实现](laowadi/storage.py) · [回放实现](laowadi/monitor.py) · [现场资料](../../项目知识库/老洼地智能体知识库.html#materials)

## 三、身份、数据边界与审计

下面的安全判断来自源码和配置阅读，未对运行中的系统做攻防测试。服务默认绑定本机。共享值班或部署到矿方网络时，必须重新验收实际可达边界。

| 编号 | 证据 | 问题与影响 |
| --- | --- | --- |
| 23 | 实现 | **身份和角色缺乏可信来源。** 默认模式把本机用户视为工程师；签发流程缺少对真实主体及其获准角色的认证。开启强制鉴权能检查令牌，但岗位授予、调岗撤权、令牌吊销和签名密钥轮换都缺少可核验的人事与运维流程。 |
| 24 | 实现 | **角色授权没有细到数据对象。** 会话、复核和历史记录主要按编号读取，未见按用户、班组、矿站或工单检查归属。共享班次可以是业务要求，但共享范围、私有草稿和可更改哪些记录需要明确授权。 |
| 25 | 实现 | **不同运行方式不保证同等防护。** 依赖导入失败时工作台可退回旧 HTTP 服务，FastAPI 治理中间件随之缺席。常规前端请求也没有统一携带身份凭据的机制，令牌演示集中在治理面板。严格模式须通过整套日常值班操作验收；依赖缺失应显式报错。 |
| 26 | 实现 | **模型的数据边界与项目约定不一致。** 受限查数让模型选只读候选；深度诊断可把复核记忆、对话历史和压缩工具结果交给已配置模型，协同会诊还可发送专家摘要供模型撰写结论。若使用外部网关，需明确获准字段、用途、保留期及责任人。本轮未发送模型请求，也未核查既往网关留存。 |
| 27 | 实现 | **本机哈希链不足以单独支持操作追责。** 中间件记录的请求摘要主要覆盖查询串和客户端信息，未把每次复核正文、补证版本、业务结果与责任人完整绑定；复核署名来自提交表单。链头缺独立保全的可信依据，仍需异机或独立权限域的留存与核对。 |
| 28 | 实现、待举证 | **矿网接入和资料全生命周期缺交付证据。** 当前有本机访问限制、只读数据连接和文本拦截规则。未见矿方确认的采集网络分区、最小权限账号、跨区访问路径、原件下载授权和日志、会话与备份保留期限。需要与信息化、机电及资料所有方逐项确认。 |

## 投产决定应依据的三次验收

1. **离线纠错。** 先把错单位、无出处、无日报日期、反向补证、分批补证、串日复核、空值、首日启动、更正帧及通知失败加入验收。由独立答案判定事实、待查项、送达结果和最终状态。上述场景均可在本地完成，无须新增现场资料。
2. **矿方影子试运行。** 维持现行值班流程，系统只读旁路。使用后续老洼地数据；让值班员独立记录事件、实际工况与处理时间，再与系统结果对照。按同一事件计发现、送达、签收、处置和交接时间；尚无对应故障样本的能力继续挂牌待验。
3. **正式交付。** 在矿方目标环境验证身份与岗位、外发数据边界、发布回退和断电恢复，签收当班使用范围、业务指标、值守人及退出方案。潮流、保护、转供等工程用途另以现场参数、有效图纸及专业复核验收。

本轮运行了本地导入与回放校验、36 题综合基准、归档单元格与两天日均的独立核对，以及上文注明的隔离反例。模拟更正、缺测、通知失败和复核写入使用内存或临时文件；综合基准前后日报库、事件库哈希一致。本轮未访问矿方网络、未调用真实模型、未执行安全攻击测试，也未进行生产容量测试。清单记录的是当前交付证据；现场性能、故障准确率、其他企业仓库及矿方制度仍待相应责任人举证。
